# Контракт: подкоманды наряда в `au task`

Единственная граница между сменой и базой. Смена не открывает SQLite никогда — все обращения идут сюда.

Контракт держится на **кодах возврата**, а не на разборе текста вывода. Причина прямая: FR-010 требует отличать «нарядов нет» от «база занята», и если это различие живёт в человекочитаемой строке, то первый же `SQLITE_BUSY` от ручной сессии владельца будет прочитан как пустая очередь, и смена выйдет в час ночи, отчитавшись об успехе.

## Общие правила

- Каждая подкоманда поддерживает `--json`; смена всегда вызывает с ним.
- Коды возврата: `0` — получилось, `10` — нечего делать (не ошибка), `11` — база занята, `1` — всё остальное.
- Классификация занятости берётся из кода ошибки SQLite, не из текста сообщения — этого прямо требует принцип III конституции.
- Ни одна подкоманда не удаляет и не перезаписывает чужие поля: только добавляет свои ключи через `json_set`.

## `au task claim`

Берёт один наряд из машинного пула.

```
au task claim --owner <строка> --run <строка> --lease-minutes <N> [--project <имя>] --json
```

Отбор: тип узла — задача, не удалена, вердикт `machine`, попыток меньше трёх, остывание прошло, и статус либо `backlog`, либо `active` с истёкшей арендой. Порядок: приоритет, затем число прошлых попыток, затем возраст.

Взятие — одно предложение `UPDATE ... RETURNING`, а не «прочитать, подумать, записать». Второй писатель либо ждёт по `busy_timeout`, либо видит наряд уже занятым (FR-006).

| Код | Значение | Что делает смена |
|---|---|---|
| `0` | Наряд выдан, в выводе — задача с критериями приёмки и досье прошлых попыток | Запускает звено |
| `10` | Исполнимых нарядов нет | Считает подряд идущие пустые ответы; три подряд с интервалом в минуту — выход и сводка |
| `11` | База занята другим писателем | Ждёт и повторяет. **Пустой очередью не считает** |

## `au task renew`

Продлевает аренду взятого наряда. Вызывает смена, пока дочерний процесс жив, — не исполнитель (FR-009).

```
au task renew --id <идентификатор> --owner <строка> --lease-minutes <N> --json
```

| Код | Значение |
|---|---|
| `0` | Аренда продлена |
| `10` | Наряд уже не принадлежит этому владельцу — истёк и перевыдан |
| `11` | База занята |

## `au task release`

Заявляет исход работы. **Не закрывает задачу сам** — заявка пишет намерение, решение принимает смена (FR-012).

```
au task release --id <идентификатор> --owner <строка> --verdict done|failed --evidence "<команда>" --json
```

- `--verdict done` принимается только при выполнении всех трёх условий сразу: код возврата звена ноль, есть успешная проверка позже момента взятия наряда, по каждому критерию приёмки есть запись о проверке. Не сошлось — задача возвращается в очередь, `attempts` уже увеличен (FR-013).
- `--verdict failed` возвращает наряд в очередь и ставит остывание.
- Закрытая автоматически задача помечается `done_by=smena` — это позволяет отменить результаты ночи одним запросом (FR-015).

| Код | Значение |
|---|---|
| `0` | Исход записан, в выводе — принятое решение и по каким условиям |
| `10` | Наряд не принадлежит этому владельцу |
| `11` | База занята |

## `au task give-up`

Отдельный исход: исполнитель распознал упор в человека. Задача блокируется с причиной и **в пул не возвращается** — сдача есть информация человеку, а не повод для повтора (FR-014).

```
au task give-up --id <идентификатор> --owner <строка> --why "<причина>" --json
```

## `au task fitness`

Ставит вердикт исполнимости. Единственное поле, которое эта подкоманда имеет право менять, — `fitness` (FR-003).

```
au task fitness --id <идентификатор> --verdict machine|human|split --why "<обоснование>" --json
au task fitness --dry-run [--project <имя>] --json     # сухой прогон по всей очереди
```

- `--why` обязателен и не может быть пустым: разметка автоматическая, обоснование — единственный способ обнаружить её ошибку утром (FR-003a).
- Вердикт записывается вместе с хешем содержания задачи. Текст задачи изменили — вердикт недействителен (FR-004).
- `--dry-run` ничего не пишет и печатает вердикт по каждой открытой задаче. Это режим волны 0: он отвечает числом на вопрос, сколько задач очереди вообще исполнимо машиной (SC-001).

## Что в контракт не входит

MCP-инструменты не добавляются и не меняются. Поверхность, которую видят чужие агенты, остаётся прежней — принцип VI конституции не затрагивается вовсе.
