# Tasks: Круг «задача — работа — улика — закрытие»

**Input**: Design documents from `/specs/007-task-evidence-loop/`
**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/cli.md, quickstart.md

**Tests**: включены. Не по умолчанию, а по конституции: принцип V требует автоматический тест с
асимметрией «падает до правки, проходит после», а гейты `fmt` / `clippy` / `test` объявлены
обязательными для каждого изменения.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: можно вести параллельно (разные файлы, нет зависимости от незакрытых задач)
- **[Story]**: к какой истории относится (US1…US5)
- В описании — точный путь к файлу

## Path Conventions

Рабочее дерево — рабочая область Rust: `crates/aurelius-core/`, `crates/au/`, `crates/aurelius/`.
Обвязка ulika живёт в отдельном репозитории `A:/workSpace/ulika/` и правится своим PR.

## Implementation Strategy

**MVP** — Phase 1, 2, 3. Это US1: задачи начинают предъявляться сами. Ровно та боль, ради которой
всё затевалось; остальное улучшает точность памяти, но не закрывает её.

**Быстрая победа до MVP** — Phase 5 (US3): три задачи, одна строка правки, эффект на каждую
длинную сессию. Разумно сделать первой, если нужен видимый результат сегодня.

**Дальше по убыванию** — US2 (дамп станет честным), затем US5 (чистка, не ломающая ничего кроме
двух неиспользуемых команд), затем US4 (секреты — самая аккуратная часть, цена ошибки высока).
