# Contract: режим `--hook` у `au touch`, `au reindex`, `au db backup`

Общее для всех трёх:

- `--hook` читает JSON события Claude Code из stdin (может быть пустым или не-JSON — тогда
  событие игнорируется).
- Код возврата **всегда 0**. Любая внутренняя ошибка (нет базы, нет прав, нет сети, нет файла)
  завершает процесс молча. При `AURELIUS_HOOK_DEBUG=1` причина печатается в stderr одной строкой
  `au <cmd> --hook: <reason>`.
- stdout пуст (эти три хука не отдают контекст в сессию).
- Без `--hook` поведение подкоманд не меняется.

## `au touch --hook`

Заменяет `contrib/claude-code/aurelius-track-edit.sh`.

| Шаг | Правило |
|---|---|
| Путь | `tool_input.file_path`, иначе `tool_input.path`; пусто → выход 0 |
| Существование | путь не является обычным файлом → выход 0 |
| Действие | то же, что `au touch <path>`: `access_count += 1` у существующего узла файла; узлы **не создаются** |
| Конфликт аргументов | `au touch --hook <PATH>` — ошибка разбора clap (флаг и позиционный аргумент взаимно исключающие) |

Тесты: разбор трёх образцов JSON (`file_path`, только `path`, ни того ни другого); не-JSON на
stdin → `Ok(())` без обращения к базе.

## `au reindex --hook`

Заменяет `contrib/claude-code/aurelius-reindex.sh`.

| Шаг | Правило |
|---|---|
| Корень | `cwd` из полезной нагрузки, иначе текущий каталог процесса; затем `git rev-parse --show-toplevel` от него, при неудаче — сам каталог |
| Действие 1 | `au reindex --path <корень>` (существующая логика) |
| Действие 2 | `au share push` для всех sync-проектов (существующая логика, best-effort) |
| Отказ действия 1 | не отменяет действие 2 |
| Конфликт аргументов | `--hook` и `--path` вместе — ошибка разбора clap |

Тесты: разбор `cwd` из образца; отсутствие `cwd` → текущий каталог; подъём до корня git на
временном репозитории.

## `au db backup --hook [--keep N] [--min-hours H]`

Заменяет `contrib/claude-code/aurelius-backup.sh`.

| Шаг | Правило |
|---|---|
| Параметры | `--keep` (по умолчанию `AURELIUS_BACKUP_KEEP`, иначе 7), `--min-hours` (по умолчанию `AURELIUS_BACKUP_MIN_HOURS`, иначе 24); флаг сильнее переменной; значения < 1 → выход 0 с debug-строкой |
| База | `db_path()` — тот же путь, что у всех команд; файла нет → выход 0 |
| Каталог | `<data_dir>/backups`, создаётся при отсутствии |
| Троттлинг | новейший `aurelius-*.db` моложе `min_hours` часов по mtime → выход 0 |
| Снимок | `aurelius-<UTC %Y%m%dT%H%M%SZ>.db` через существующий `VACUUM INTO` |
| Проверка | существующий `db check` на снимке; провал → переименовать в `<имя>.FAILED-CHECK`, удалить `<имя>-wal` и `<имя>-shm`, выход 0 |
| Ротация | оставить `keep` новейших `aurelius-*.db` по mtime, остальные удалить; `.FAILED-CHECK` не трогаются |
| Конфликт аргументов | `--hook` и `--out` вместе — ошибка разбора clap |

Тесты: на временном `AURELIUS_HOME` — первый вызов создаёт снимок, второй сразу за ним не
создаёт (троттлинг), `--min-hours 0` создаёт, `--keep 2` после трёх снимков оставляет два
новейших; логика троттлинга и ротации вынесена в чистые функции над списком `(имя, mtime)` и
тестируется без файловой системы.

## Реальный прогон (принцип V)

```
echo '{"tool_input":{"file_path":"/tmp/x.rs"}}' | au touch --hook; echo $?          # 0
echo 'not json' | au reindex --hook; echo $?                                          # 0
AURELIUS_HOME=$(mktemp -d) sh -c 'au init >/dev/null; au db backup --hook; au db backup --hook; ls $AURELIUS_HOME/backups'  # ровно один файл
```
