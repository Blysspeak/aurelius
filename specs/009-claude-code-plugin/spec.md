# Feature Specification: Плагин Claude Code для aurelius

**Feature Branch**: `009-claude-code-plugin`
**Created**: 2026-09-05
**Status**: Draft
**Input**: задача `a4b486b3` (проект aurelius). Упаковать интеграцию aurelius с Claude Code —
MCP-сервер, хуки, указатель на карточки, команда подъёма — в плагин Claude Code, который
ставится одной командой и версионируется вместе с релизом. `install.sh` перестаёт править
`~/.claude/settings.json` и `~/.claude.json`.

## Почему это вообще заводится

Сегодня интеграция собирается вручную из трёх мест. `install.sh` копирует четыре bash-обёртки в
`~/.claude/hooks` и python-блоком дописывает их в `settings.json`. Ещё три хука (`au snapshot`,
`au trace`, `au judge`) и регистрация MCP-сервера в `~/.claude.json` поставлены руками и в
`install.sh` не отражены вовсе. Сам `install.sh` регистрирует сервер в `settings.json` командой
`au mcp`, а живой сервер этой машины запущен из `~/.local/share/mcp/aurelius` — три источника
описывают три разные конфигурации (факт `227dc31b` в au).

У владельца две машины, Linux и Windows. На второй всё это повторяется руками, и bash-обёртки
там требуют Git Bash плюс python3. Каждый релиз aurelius, меняющий хук, снова требует ручной
правки двух JSON-файлов на каждой машине; забытая правка означает старый хук против нового
бинарника, и заметно это становится только по «unknown tool».

Плагин Claude Code — документированный способ нести MCP-сервер, хуки, скиллы и команды одним
каталогом: ставится одной командой из git-репозитория, обновляется по версии, включается и
выключается без правки JSON руками. Это про переносимость, не про удобство агенту: корректность
интеграции живёт в схемах MCP-инструментов и в самих хуках, и туда плагин ничего не добавляет.

## Clarifications

### Session 2026-09-05

- Q: Какой командой плагин запускает MCP-сервер — `au mcp` или бинарник `aurelius`? → A: `au mcp`.
  Обе точки входа зовут одну функцию `aurelius::mcp::serve()`, разницы в сервере нет; `au` и так
  обязан быть в PATH ради хуков, значит в PATH нужен ровно один бинарник. Бинарник `aurelius`
  остаётся собираться для обратной совместимости, плагин им не пользуется.
- Q: Хуки в плагине — те же bash-обёртки из `contrib/claude-code`, или нативные подкоманды `au`?
  → A: нативные. Обёртки требуют bash и python3, чего на Windows без Git Bash нет, а критерий
  задачи — работа на обеих ОС. Три хука уже нативны (`au skills --hook`, `au snapshot --hook`,
  `au trace --hook`, `au judge --hook`); логика трёх обёрток переезжает в `au`: отметка правки
  файла (`aurelius-track-edit.sh`), переиндексация с публикацией (`aurelius-reindex.sh`),
  снимок базы с троттлингом и ротацией (`aurelius-backup.sh`). Обёртки в `contrib/` остаются
  до следующего мажора для тех, кто ставил руками.
- Q: Какие хуки несёт плагин — только четыре из `install.sh` или все семь живых? → A: все семь
  aurelius-хуков живого `settings.json`: SessionStart (индекс карточек, снимок памяти, бэкап
  базы), PostToolUse (отметка правки на Edit|Write, трасса действий на Bash|PowerShell|Edit|
  Write|NotebookEdit), Stop (переиндексация, вердикты судьи). `aurelius-save-reminder.mjs` — не
  из этого репозитория, в плагин не входит.
- Q: Где лежит плагин в репозитории? → A: в корне: `.claude-plugin/plugin.json` рядом с
  `Cargo.toml`. Так плагин ставится прямо из git-репозитория одной командой без отдельного
  маркетплейса, а для разработки подключается локальным каталогом. Отдельная директория
  потребовала бы маркетплейс-манифест — лишний слой ради того же результата.
- Q: Как версия плагина держится равной версии workspace? → A: поле `version` в манифесте пишется
  явно и проверяется тестом workspace: расхождение — красный `cargo test`, то есть красный гейт
  релиза. Фолбэк Claude Code на `Cargo.toml` при отсутствии поля отвергнут: неявное правило, о
  котором надо помнить, хуже явного числа с проверкой.
- Q: Что делать со старыми записями в `settings.json` и `~/.claude.json`? → A: `install.sh`
  снимает их сам, с бэкапом файла и печатью того, что снято и почему. Иначе хуки дублируются:
  хуки плагина сливаются с `settings.json` без дедупликации, каждый сработает дважды; а MCP-сервер
  из `~/.claude.json` перекрывает плагинный целиком — плагин молча не работает.

## User Scenarios & Testing *(mandatory)*

### User Story 1 — Установка на чистом профиле (Priority: P1)

Человек ставит бинарники aurelius в PATH и одной командой ставит плагин. Открывает новую сессию
Claude Code в любом проекте: снимок памяти и индекс карточек приходят при старте, `memory_status`
отвечает, правки файлов отмечаются, при завершении хода проект переиндексируется, раз в сутки
снимается бэкап базы. Ни `settings.json`, ни `~/.claude.json` руками не трогались.

**Why this priority**: это и есть смысл фичи — вторая машина владельца поднимается без ручной
сборки интеграции по памяти.

**Independent Test**: свежий профиль Claude Code (пустой `~/.claude`, без `~/.claude.json`),
бинарники в PATH, одна команда установки плагина, новая сессия; проверяется наличие семи
срабатываний хуков в журнале и ответ `memory_status`.

**Acceptance Scenarios**:

1. **Given** чистый профиль и `au` в PATH, **When** плагин установлен и открыта новая сессия,
   **Then** в контексте сессии есть снимок памяти и индекс карточек, `memory_status` отвечает
   блоком `server` с версией, равной версии плагина.
2. **Given** сессия с плагином, **When** агент правит файл через Edit или Write, **Then** узел
   файла в памяти получает отметку доступа — тем же способом, что и при ручной установке.
3. **Given** сессия с плагином, **When** ход завершается, **Then** проект переиндексирован и
   вердикты судьи применены, как при ручной установке.
4. **Given** чистый профиль без `au` в PATH, **When** открыта сессия, **Then** сессия работает,
   хуки не блокируют её, и в контексте есть одна строка о том, что бинарник не найден и как его
   поставить.

---

### User Story 2 — Миграция машины с ручной установки (Priority: P1)

На машине владельца интеграция уже стоит руками: семь хуков в `settings.json`, сервер в
`~/.claude.json`, обёртки в `~/.claude/hooks`. Человек запускает обновлённый `install.sh`. Тот
собирает бинарники, ставит плагин и снимает старые записи, показывая список снятого с причиной.
После рестарта каждый хук срабатывает ровно один раз, MCP-сервер отвечает из плагина.

**Why this priority**: без этого шага установка плагина на существующей машине ухудшает
положение — хуки бьют дважды, а плагинный сервер перекрыт старой записью.

**Independent Test**: текущая Linux-машина владельца; после `install.sh` в журнале одной сессии
каждое событие даёт по одному срабатыванию каждого aurelius-хука; в `settings.json` и
`~/.claude.json` нет записей aurelius; рядом лежат их бэкапы с датой.

**Acceptance Scenarios**:

1. **Given** `settings.json` с семью aurelius-хуками и `~/.claude.json` с сервером aurelius,
   **When** запущен `install.sh`, **Then** обе записи сняты, файлы сохранены в бэкап с датой в
   имени, в выводе перечислено каждое снятое с причиной («переехало в плагин»).
2. **Given** те же файлы, **When** `install.sh` запущен второй раз, **Then** он ничего не снимает
   и не дублирует, сообщает, что миграция уже сделана.
3. **Given** в `settings.json` есть чужие хуки (ulika, `aurelius-save-reminder.mjs`), **When**
   запущен `install.sh`, **Then** чужие хуки не тронуты.
4. **Given** плагин установлен, **When** сессия открыта и завершена, **Then** каждый aurelius-хук
   отработал по одному разу на событие.

---

### User Story 3 — Та же интеграция на Windows (Priority: P2)

На Windows-машине бинарники стоят в PATH, плагин установлен той же командой. Хуки срабатывают
без Git Bash и python3, пути в манифесте не зависят от разделителя.

**Why this priority**: вторая машина владельца — Windows; без этого фича закрывает половину
задачи.

**Independent Test**: Windows-профиль Claude Code без Git Bash и python3 в PATH; сессия открыта
и завершена; журнал показывает срабатывания всех семи хуков без ошибок «команда не найдена».

**Acceptance Scenarios**:

1. **Given** Windows без Git Bash и python3, **When** открыта и завершена сессия, **Then** все
   семь хуков отработали, ни один не упал на отсутствующем интерпретаторе.
2. **Given** любая из двух ОС, **When** читается манифест хуков, **Then** в нём нет команд,
   зависящих от оболочки: каждая команда — вызов `au` с аргументами.

---

### User Story 4 — Версия плагина в ногу с релизом (Priority: P2)

Релиз aurelius поднимает версию workspace. Версия плагина поднимается тем же коммитом; если
кто-то забыл — проверка проекта красная, релиз не проходит.

**Why this priority**: обновление плагина у пользователей идёт по версии; расхождение означает,
что новый бинарник встречает старый манифест хуков.

**Independent Test**: изменить версию в одном из двух мест — проверка проекта падает с
сообщением, называющим оба значения.

**Acceptance Scenarios**:

1. **Given** версии равны, **When** проверка проекта, **Then** зелёная.
2. **Given** версия манифеста отстаёт, **When** проверка проекта, **Then** красная, сообщение
   называет обе версии.

---

### User Story 5 — Подъём и карточки из плагина (Priority: P3)

В любой сессии с плагином доступна команда подъёма состояния (то, что сейчас делает личная
`/pickup`: снимок памяти, открытые задачи, состояние git) и скилл-указатель, который говорит
агенту, что карточки au лежат в памяти aurelius и достаются через `skill_get`, а не копируются.

**Why this priority**: полезно, но интеграция работает и без этого; личная команда владельца
продолжает работать параллельно.

**Independent Test**: в сессии с плагином команда подъёма перечислена среди доступных под
пространством имён плагина и выдаёт снимок; скилл-указатель виден в списке скиллов.

**Acceptance Scenarios**:

1. **Given** сессия с плагином, **When** вызвана команда подъёма, **Then** в ответе снимок
   памяти проекта, открытые задачи и состояние git.
2. **Given** сессия с плагином, **When** агент читает скилл-указатель, **Then** он получает
   инструкцию идти за карточками в `skill_get`, а не текст карточек.

---

### Edge Cases

- `au` не в PATH или старше плагина: хуки не должны ронять сессию; одна строка контекста
  называет причину и шаг установки. `memory_status` уже сообщает версию сервера — расхождение с
  версией плагина видно первым вызовом.
- Плагин установлен, а старая запись MCP в `~/.claude.json` осталась (пользователь не запускал
  `install.sh`): плагинный сервер перекрыт целиком. `install.sh` — единственный путь миграции;
  README называет это явно.
- Плагин и старые хуки одновременно: каждое событие даёт двойное срабатывание. Снятие старых
  записей обязано быть частью установки, не отдельным шагом.
- Хук бэкапа на первом запуске в сутки может занять секунды на большой базе: таймаут хука
  сохраняет сегодняшние 30 секунд; неуспешный бэкап никогда не блокирует сессию.
- Плагин установлен в проектной области, а не пользовательской: хуки работают только в этом
  проекте — допустимо, документируется как выбор.
- Два разных бинарника (`au` из PATH и `aurelius` из `~/.local/share/mcp`) с разными версиями
  после миграции: плагин пользуется только `au`; старый симлинк `install.sh` не удаляет, но
  называет в выводе как более не нужный.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Репозиторий содержит каталог плагина Claude Code в корне: манифест плагина с именем
  `aurelius`, конфигурацию MCP-сервера, манифест хуков, каталог скиллов с указателем на карточки
  и каталог команд с командой подъёма.
- **FR-002**: Конфигурация MCP-сервера запускает сервер командой `au mcp`, бинарник берётся из
  PATH; в плагине бинарников нет.
- **FR-003**: Манифест хуков регистрирует семь aurelius-хуков живой установки с теми же событиями,
  матчерами и таймаутами: SessionStart — индекс карточек, снимок памяти, бэкап базы; PostToolUse
  `Edit|Write` — отметка правки файла; PostToolUse `Bash|PowerShell|Edit|Write|NotebookEdit` —
  трасса действий; Stop — переиндексация, вердикты судьи.
- **FR-004**: Каждая команда хука — прямой вызов `au` с аргументами в exec-форме, без bash,
  python3 или иного интерпретатора; полезная нагрузка события читается самим `au` из stdin.
- **FR-005**: `au` умеет нативно то, что делали три bash-обёртки: отметить правку файла из
  события Edit|Write; переиндексировать проект из текущего каталога и опубликовать общие проекты;
  снять бэкап базы не чаще раза в сутки и хранить не больше семи снимков. Поведение и пороги
  совпадают с обёртками.
- **FR-006**: Отказ любого хука (нет бинарника, нет базы, нет сети) не блокирует сессию и не
  роняет ход; при отсутствии бинарника хук отдаёт в контекст одну строку с причиной и шагом
  установки.
- **FR-007**: `install.sh` собирает и ставит бинарники, ставит плагин и больше не пишет в
  `settings.json` и `~/.claude.json`.
- **FR-008**: `install.sh` снимает старые записи aurelius — хуки, ссылающиеся на обёртки из
  `~/.claude/hooks/aurelius-*` или на команды `au … --hook`, и сервер `aurelius` в `mcpServers`
  обоих файлов — с бэкапом каждого изменённого файла (дата в имени) и печатью каждой снятой
  записи с причиной. Чужие записи не трогаются. Повторный запуск идемпотентен.
- **FR-009**: Версия плагина записана в манифесте явно и равна версии workspace; проверка проекта
  падает при расхождении, называя обе версии.
- **FR-010**: Скилл-указатель не содержит текста карточек au — только инструкцию получать их через
  `skill_get` по имени и ссылку на индекс.
- **FR-011**: Команда подъёма даёт снимок памяти проекта, открытые задачи и состояние git — то же,
  что личная команда владельца сегодня; личная команда продолжает работать.
- **FR-012**: README описывает установку через плагин (чистая машина и миграция), CHANGELOG
  получает запись в Unreleased.
- **FR-013**: Обёртки в `contrib/claude-code` остаются в репозитории с пометкой «устарело,
  заменено плагином» до следующего мажорного релиза.

### Key Entities

- **Манифест плагина**: имя, версия (равна версии workspace), описание, указатели на конфигурацию
  MCP, манифест хуков, скиллы и команды.
- **Набор хуков**: семь пар «событие + матчер → команда `au` + таймаут»; единственный источник
  истины о том, что aurelius делает в сессии Claude Code.
- **Запись MCP-сервера**: имя `aurelius`, команда `au mcp`; должна существовать ровно в одном
  месте — в плагине.
- **Наследные записи**: хуки и сервер, поставленные `install.sh` прошлых версий или руками; объект
  миграции, распознаются по командам.
- **Установщик**: `install.sh`; сборка, установка бинарников, установка плагина, миграция.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: На чистом профиле от «бинарники в PATH» до работающего `memory_status` и снимка при
  старте — одна команда установки плагина и один рестарт; ноль ручных правок JSON.
- **SC-002**: После миграции на машине владельца каждое событие сессии даёт ровно одно
  срабатывание каждого aurelius-хука; дублей ноль по журналу хуков за сессию.
- **SC-003**: На Windows без Git Bash и python3 все семь хуков отрабатывают без ошибок за одну
  сессию.
- **SC-004**: В `install.sh` не остаётся кода, пишущего в `settings.json` или `~/.claude.json`,
  кроме миграционного снятия записей с бэкапом.
- **SC-005**: На каждом релизном теге версия манифеста плагина равна версии workspace; расхождение
  ловится проверкой проекта до релиза.
- **SC-006**: Установка на второй машине владельца занимает меньше пяти минут от клона до первой
  рабочей сессии, без обращения к памяти или к другой машине.

## Assumptions

- Claude Code на обеих машинах поддерживает плагины с манифестом хуков, конфигурацией MCP,
  скиллами и командами внутри плагина, установку из git-репозитория и локального каталога,
  подстановку корня плагина в командах (факт `0afc5d2e`).
- Бинарники ставятся в каталог, который есть в PATH у процесса Claude Code: `~/.local/bin` на
  Linux, каталог cargo или `%USERPROFILE%\.local\bin` на Windows; сборка — `cargo build --release`
  на каждой машине, готовых бинарников в релизе нет.
- Плагин ставится в пользовательскую область по умолчанию; проектная область — осознанный выбор
  пользователя, не требование.
- Хуки ulika, `aurelius-save-reminder.mjs` и git-хук `post-commit` из `contrib/git-hooks` вне
  объёма: первые два — другие проекты, третий не относится к Claude Code и ставится `install.sh`
  как сегодня.
- Карточки au остаются в памяти aurelius (решение `d70969e2`): плагин несёт только указатель.
- Личная команда `/pickup` владельца остаётся в `~/.claude/commands`; плагинная — под
  пространством имён плагина, без конфликта.
- Публикация в маркетплейс Claude Code не требуется: установка идёт из git-репозитория.
