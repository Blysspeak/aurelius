# «БИТ-И-ДЕЛО» — двухвалютный гроссбух памяти (Aurelius v2, 7 ступеней)

Ни у кого этого нет, потому что все существующие системы измеряют ценность памяти мнением — LLM-судьи (Memory-R1, Copilot Memory), эмбеддинг-сходство (mem0, Zep), либо суррогаты вроде recency/access_count (MemGPT, Letta), а surprise-гейты (EM-LLM, Titans) и реконсолидация (bitterbot, vestige, MSR) работают только на входе или только на чтении, никогда не замыкая петлю через факт. «Бит-и-дело» вводит две **измеренные** валюты и ни одной оценочной: запись зарабатывает **биты** — фактическую маржинальную экономию сжатия будущего потока сессий (сжали со словарём⊕дельта и без — разница в байтах), и зарабатывает **исход** — вердикт детерминированного судьи по сырым следам действий (exit codes, хэши состояния до/после, revert-ы, негативные коррекции пользователя), атрибутированным к лабильному окну, открытому конкретным recall-ом. Промахи бьют не по узлу, а по пути извлечения (query_sig→node); запись без машинно-проверяемых проб не рождается полноценной; всё содержимое меняется только append-ревизией с указанием окна-причины; в контуре ценообразования нет ни одного вызова LLM и ни одного эмбеддинга. Такой замкнутый измерительный контур — «предсказал ли ты вход» плюс «сработало ли действие по тебе» — не реализован ни в одной из задокументированных систем; по отдельности prior art есть у каждого столпа, композиция и обе метрики-измерения свободны.

## Обзор конвейера

```
                    Claude Code hooks (бесплатный WAL)
                              │
  ┌──────────── 1. ЖУРНАЛ СЛЕДОВ (act_trace) ────────────┐
  │                                                       │
  ▼ (кандидаты в память)                    ▼ (поток сессии)
2. ШЛЮЗ: сюрприз + пробы          5. КЛИРИНГ: биты по когортам
  │                                         ▲
  ▼                                         │
3. RECALL: окно + путь ──► 4. СУДЬЯ ИСХОДА ─┘
  │                              │
  ▼                              ▼
6. ПРОСПЕКТИВНЫЙ КОНТУР    7. АССИМИЛЯЦИЯ / БАНКРОТСТВО
(обязательства, намерения)  (в словарь / поглощение соседом)
```

Две валюты сходятся в одном счёте узла: `value = α·bits + β·yield`, обе — из измерений, коэффициенты калибруются обратным каналом рендера (ступень 5), а не настраиваются руками.

## Ступень 1. Журнал следов (act-trace WAL)

**Механика.** Единственная точка входа конвейера. Каждое событие агента — вызов тула, правка файла, ошибка, git-коммит, отправленное сообщение, коррекция пользователя — пишется как сырой след без интерпретации: вид, полезная нагрузка, код возврата, хэш затронутого состояния до/после (для файлов — blake3 содержимого, для git — HEAD). Хуки Claude Code (PostToolUse, UserPromptSubmit, Stop) дают поток бесплатно; tg-mcp и коммиты доливаются через тот же вход. Никакой семантики: память дальше строится не из «что агент узнал», а из «что агент сделал и чем это кончилось».

**Схема.**
```sql
act_trace(
  id INTEGER PRIMARY KEY, ts INTEGER, session_id TEXT,
  kind TEXT,            -- tool_call|file_edit|error|commit|msg_sent|user_correction
  payload TEXT,         -- усечённый текст/аргументы, идёт в FTS5
  exit_code INTEGER, state_hash_pre TEXT, state_hash_post TEXT
);
CREATE TRIGGER act_trace_ro BEFORE UPDATE ON act_trace BEGIN
  SELECT RAISE(ABORT,'append-only'); END;
-- + act_trace_fts (FTS5, contentless, по payload)
```

**Срабатывает:** хуки PostToolUse/Stop/UserPromptSubmit (уже есть SessionStart/Stop — добавить PostToolUse); внутри aurelius — при `memory_add`, `task_update`, отправке через tg-тулы.

## Ступень 2. Шлюз: сюрприз + пробный гейт

**Механика.** Кандидат в память проходит два детерминированных фильтра.

*Сюрприз (из SL):* сжимаем текст против zstd-словаря своего scope (проект × тип узла) и против пустого словаря; NCS = C(x|dict)/C(x|null). NCS ниже порога — молчаливый отказ: уже предсказано, ноль информации. Это копеечный дедуп-фильтр ПЕРЕД любой дорогой обработкой — то, чего нет ни у mem0, ни у Zep. Выше порога — открывается дельта-счёт с `surprisal_bits`.

*Пробы (из THYMUS):* Rust-регэкспы извлекают из тела машинно-проверяемые утверждения — пути файлов, git-SHA, имена команд, таблицы БД — и исполняют их против ground truth здесь и сейчас (`fs::metadata`, `git rev-parse`, `PRAGMA table_info`, PATH). Провал пробы — узел рождается мёртвым (`attenuated`) с автоматически отчеканенной **коррекцией** («утверждалось X, файл не существует»). Память без единой пробы получает `unverifiable=1`: циркулирует, но имеет потолок — не ассимилируется в словарь и не получает yield-бонусов.

Важное отличие от чистого SL: сырой текст НЕ выбрасывается — он живёт как ревизия в `node_version` (инвариант аудируемости из Палимпсеста). Резидуал — слой оценки, не хранения; это снимает хрупкость «памяти из одних дельт» при переобучении словарей.

**Схема.**
```sql
codec(dict_id INTEGER PRIMARY KEY, scope TEXT, epoch INTEGER, blob BLOB);
delta(
  id INTEGER PRIMARY KEY, node_id INTEGER, scope TEXT,
  residual BLOB,        -- NULL после folded (вакуум)
  raw_len INTEGER, resid_len INTEGER, surprisal_bits INTEGER,
  epoch_born INTEGER,
  status TEXT CHECK(status IN ('active','assimilating','folded','inverted'))
);
probes(
  id INTEGER PRIMARY KEY, node_id INTEGER,
  kind TEXT CHECK(kind IN ('file_exists','git_sha','cmd_in_path','table_in_schema')),
  expr TEXT, last_ok INTEGER, checked_at INTEGER
);
-- nodes получает колонки: state ('naive','circulating','memory_cell','attenuated'),
-- unverifiable INTEGER DEFAULT 0
```

**Срабатывает:** `memory_add`, `memory_session`, `doc_convert/ingest`.

## Ступень 3. Recall = лабильное окно + путь извлечения

**Механика.** `memory_recall` / `memory_context` / хит `memory_search` — больше не чистый SELECT. Атомарно:

1. **Коррекции первыми** (контрактная гарантия из THYMUS): запрос сперва матчится об FTS-таблицу `corrections`; совпавшие подаются ДО результатов — «раньше считалось X, теперь Y, причина: пере-проверка пробы провалилась». Забывание — активная подача поправки, а не дыра в выдаче.
2. **Путь:** пишется/обновляется строка `pathways(query_sig, node_id)` — minhash-сигнатура запроса против узла. Заблокированные пути (`blocked=1`) вычёркивают узел из выдачи ЭТОГО запроса, оставляя достижимым другими формулировками.
3. **Окно:** создаётся `labile_window` со снапшот-хэшем содержимого; все последующие `act_trace` сессии, чьи FTS-токены пересекаются с узлом, атрибутируются к окну (`trace_attribution`). Одно открытое окно на узел на сессию (частичный UNIQUE).
4. **Премия открытия** (из Мнемобиржи): если узел найден через search, но НЕ входил в отрендеренный снапшот этой сессии — проводка `kind='discovery'` в гроссбух: рынок его недооценил, на следующем рендере у него больше капитала. Это детерминированная замена reflection-циклам.

Узлы отдаются с явной меткой статуса: «не подтверждено использованием» / «подтверждено N исходами» — агент видит, чему память сама не доверяет.

**Схема.**
```sql
labile_window(
  id INTEGER PRIMARY KEY, node_id INTEGER, session_id TEXT,
  snapshot_hash TEXT, opened_at INTEGER, closed_at INTEGER,
  verdict TEXT CHECK(verdict IN ('reinforce','erode','fork','null'))
);
CREATE UNIQUE INDEX lw_one_open ON labile_window(node_id, session_id)
  WHERE closed_at IS NULL;
pathways(
  query_sig TEXT, node_id INTEGER, confirms INTEGER DEFAULT 0,
  misfires INTEGER DEFAULT 0, blocked INTEGER DEFAULT 0,
  PRIMARY KEY(query_sig, node_id)
);
trace_attribution(window_id INTEGER, trace_id INTEGER, overlap_score REAL);
corrections(
  id INTEGER PRIMARY KEY, fts_pattern TEXT, dead_node_id INTEGER,
  replacement_id INTEGER, reason TEXT, minted_at INTEGER
); -- + corrections_fts (FTS5)
```

**Срабатывает:** тулы `memory_recall`, `memory_context`, `memory_search`.

## Ступень 4. Дифф-судья исхода (сердце «дела»)

**Механика.** Самая дефицитная часть по всем вердиктам скептиков — никто не замыкает петлю через фактический исход инструментального действия. При закрытии окна (Stop-хук или таймаут) чистая Rust-функция `(snapshot, attributed_traces) -> Verdict` выносит вердикт БЕЗ LLM:

- **reinforce** — действие по содержимому узла завершилось success-следом: команда из узла прошла с exit 0; файл по упомянутому пути реально изменён (state_hash_pre ≠ post); тест зелёный после правки.
- **erode** — error-след сразу после использования; revert упомянутого файла (hash_post == более ранний hash_pre); `user_correction`-след с отрицанием токенов узла («нет», «не так», «уже не»).
- **fork** — следы противоречивы (и success, и негация): узел не правится, создаётся узел-вариант с ребром `disputed_by`; конфликт живёт в графе и разрешается перевесом yield последующих окон, без немедленной адъюдикации.
- **null** — окно открыто, пересечений нет (прочитано-но-бесполезно; это тоже сигнал — см. ступень 7).

Применение вердикта — единственный писатель контента, **реконсолидатор**: append новой ревизии в `node_version` с `cause_window_id`. reinforce → `consolidation_level+1`; erode → к узлу пришивается structured-маркер `counter_evidence: trace_id`, и если причина — провал пере-проверенной пробы, чеканится коррекция (ступень 3). Misfire (erode/противоречие внутри окна) дебетует **путь**, не узел: `pathways.misfires+1`, M промахов → `blocked=1`. Агрегированный misfire-rate проекта поднимает порог промоции K в `memory_cell` — память ужесточает политику там, где исторически ошибалась.

**Схема.**
```sql
node_version(
  node_id INTEGER, rev INTEGER, content TEXT,
  consolidation_level INTEGER DEFAULT 0, cause_window_id INTEGER,
  PRIMARY KEY(node_id, rev)
);
CREATE TRIGGER nodes_no_direct_update BEFORE UPDATE OF content ON nodes
  WHEN (SELECT flag FROM writer_gate) != 1
  BEGIN SELECT RAISE(ABORT,'content only via reconsolidator'); END;
-- writer_gate: однострочная таблица-семафор, ставится только реконсолидатором
-- edges: добавить тип 'disputed_by'
```
Инварианты: новая ревизия только при закрытом окне с непустым вердиктом; контент узла = MAX(rev).

**Срабатывает:** Stop-хук (закрывает все окна сессии), фолбэк-таймаут при следующем обращении.

## Ступень 5. Клиринг: битовая бухгалтерия с обратным каналом

**Механика.** Одна транзакция на SessionStop:

1. Поток сессии (конкатенация `act_trace.payload` + тексты реплик) сжимается со словарём scope и со словарём⊕дельта — **когортно**: активные дельты разбиты на K когорт round-robin, за сессию измеряется одна когорта (не N полных проходов). Разница в байтах кредитуется счёту дельты: `kind='earn'`.
2. **render_miss** — отрицательная проводка: дельта была в отрендеренном снапшоте, но не заработала ни бита и её узел не был процитирован — место в контексте потрачено зря. Это то, чего нет ни у кого: цена показа.
3. Начисляются `discovery`-премии, накопленные ступенью 3.
4. **Yield-мост:** закрытые окна конвертируются во вторую валюту: `action_yield(node) = Σreinforce − Σerode`, нормированный на число окон. В гроссбух — `kind='yield_bonus'` (фиксированный тариф за reinforce), чтобы обе валюты сходились в одном счёте.
5. **Калибровка:** по журналу рендера пересчитываются α/β оценщика рюкзака (ступень «снапшот» ниже) — методом наименьших квадратов по фактическим earn/miss. Оценщик со временем меряет реальную, а не предполагаемую предсказательную силу.
6. Сессия-узел получает долю заработка своих детей (след Мнемобиржи в одну строку): summary плохих сессий естественно беднеют и раньше уходят в digest.

**Схема.**
```sql
ledger(
  delta_id INTEGER, session_id TEXT, bits_delta INTEGER,
  kind TEXT CHECK(kind IN ('earn','render_miss','discovery','yield_bonus','inversion_debit')),
  PRIMARY KEY(delta_id, session_id, kind)
);
render_log(session_id TEXT, node_id INTEGER, layer TEXT, bytes INTEGER,
  cited INTEGER DEFAULT 0);
calib(id INTEGER PRIMARY KEY CHECK(id=1), alpha REAL, beta REAL, updated_at INTEGER);
-- value(delta) = SUM(ledger.bits_delta) — единственная битовая метрика,
-- timestamps в ранжировании не участвуют.
```

**Срабатывает:** Stop-хук, после ступени 4, одной транзакцией.

## Ступень 6. Проспективный контур: обязательства и намерения

**Механика.** Память о будущем как двойная бухгалтерия (ядро Zeigarnik Ledger, честно переименованное в commitment ledger).

*Intake:* детерминированная грамматика комиссивов (расширяемая таблица маркеров: «сделаю», «надо потом», «завтра», TODO/FIXME, вопросы без ответа) прогоняется по `act_trace` и текстам сессий. Квант обязательства проводится парой дебет/кредит между узлами-контрагентами (Влад, агент, мерчант, Тео); дубль схлопывается по ключу (debtor, creditor, object_fp). **Инвариант: обязательство существует ⇔ проводки не сбалансированы** — не булевый флаг, а аудируемый журнал.

*Анти-decay:* tension открытой проводки растёт (лениво, при чтении): возраст × близость дедлайна × глубина прерывания × вес контрагента из его кредитного профиля. Хронически ненадёжный контрагент (высокий breach_ratio из закрытых проводок) наращивает tension быстрее — обратная связь Settle→Accrual, которой нет в MAS-репутациях.

*Погашение:* коммит, отправленное сообщение, `task_update done`, `memory_add` типа solution прогоняются через матчер (FTS-пересечение + пара контрагентов + окно времени). Совпадение ≥ порога — кредитующая проводка, tension в ноль, дальше агрессивный decay (завершённое забывается первым). Ниже порога — в `match_queue` на подтверждение агентом: **LLM — пользователь механизма, не компонент.**

*Намерения:* взведённые SQL-предикаты («когда трогаем db.rs — вспомнить про миграцию»): fts_match, path_glob, edge_condition, deadline — проверяются на каждом входящем следе; сработавшие инжектятся в следующий SessionStart и переходят в fired.

*Стек прерываний:* Stop-хук фиксирует suspension-фрейм для всего, что трогалось, но не погашено: последний файл, последняя команда, «оборвано на...» — точка возврата, не тема.

**Схема.**
```sql
obligations(id INTEGER PRIMARY KEY, debtor_node INTEGER, creditor_node INTEGER,
  verb_class TEXT, object_fp TEXT, opened_at INTEGER, deadline INTEGER,
  src_trace INTEGER); -- + obligations_fts
ob_postings(obligation_id INTEGER, side TEXT CHECK(side IN ('debit','credit')),
  trace_id INTEGER, at INTEGER);
counterparty_profile(node_id INTEGER PRIMARY KEY,
  median_close_days REAL, breach_ratio REAL);
intentions(id INTEGER PRIMARY KEY, predicate_kind TEXT, predicate_arg TEXT,
  payload TEXT, state TEXT CHECK(state IN ('armed','fired','eroded')), armed_at INTEGER);
suspensions(session_id TEXT, obligation_id INTEGER, resume_ctx TEXT); -- JSON
match_queue(obligation_id INTEGER, trace_id INTEGER, score REAL);
```

**Срабатывает:** intake/предикаты — на каждом `act_trace`; suspend — Stop; surface — SessionStart; матчер — на погашающих видах следов.

## Ступень 7. Ассимиляция и банкротство-поглощение

**Механика.** Два выхода из активной памяти, оба детерминированные.

*Вверх — в грамматику:* дельта со стабильным заработком (`value > k·resid_len` на протяжении m сессий, `unverifiable=0`) помечается assimilating и входит в корпус переобучения словаря эпохи N+1 (фоновая транзакция: `ZDICT_trainFromBuffer`, перекодировка активных резидуалов). Её резидуал схлопывается почти в ноль → `folded`, вакуум. Долгая память — это не старые записи, а изменённое ожидание кодека: система забывает слова, выучивая грамматику.

*Дрейф-флаг (ослабленный, по вердикту скептика):* если после переобучения `resid_len` старой дельты ВЫРОС — это НЕ автоинвалидация (аллокационные артефакты кодека), а постановка в `recheck_queue`: перепрогнать пробы; провал пробы → erode-вердикт штатным путём ступени 4.

*Вниз — банкротство:* GC-ранг = `α·value_bits/resid_len + β·action_yield_norm` (α, β — из calib). Узел с 40 чтениями и нулём подтверждённых исходов деградирует раньше узла с двумя reinforce. Деградация ступенчатая: полный текст → выжимка полей → tombstone с FTS-токенами → удаление только tombstone-ов с yield<0. Ключевое (из Мнемобиржи, prior art отсутствует): банкрот **поглощается** — его входящие рёбра и остаточные требования наследует сильнейший связанный узел (вес наследования по типу ребра: solution→problem сильнее mentions), выживший получает absorbed-ссылки на архив. Граф уплотняется вокруг платёжеспособных хабов без LLM-суммаризации. Tombstone, найденный поиском трижды, принудительно возвращается в circulating (re-listing). Полная история в `node_version` делает забвение обратимым.

**Схема.**
```sql
recheck_queue(node_id INTEGER, reason TEXT, old_len INTEGER, new_len INTEGER,
  queued_at INTEGER);
receivership(node_id INTEGER, absorbed_by INTEGER, ts INTEGER);
-- nodes.degrade_stage INTEGER DEFAULT 0 (0 full, 1 digest, 2 tombstone)
-- edges: тип 'absorbed'
```

**Срабатывает:** `memory_gc` (ручной) и автоматически каждые K клирингов; переобучение словаря — фоном при накоплении assimilating-корпуса > порога.

## Что инжектится при SessionStart

Frozen snapshot v2, слои в фиксированном порядке, каждый со своим байт-бюджетом:

1. **Коррекции** (вне бюджета конкуренции, всегда первыми): FTS-матч контекста запуска (cwd, ветка, последние файлы из act_trace прошлой сессии) об `corrections` — «раньше считалось X, теперь Y, причина Z».
2. **Точка возврата:** верхний suspension-фрейм текущего проекта — последний файл, команда, «оборвано на...».
3. **Гроссбух давления:** top-K открытых обязательств по tension в двух зеркальных колонках — «ты должен» / «тебе должны, кого пнуть» — плюс payload-ы сработавших намерений.
4. **Рюкзак знаний:** жадный knapsack по `score/resid_len DESC` под бюджет слоя, где `score = α·E[bits] + β·yield` из калиброванных счетов; узлы идут с метками статуса (`memory_cell` / «не подтверждено использованием») и, для quarantined-пар, с явным конфликтом.

Всё, что отрендерено, пишется в `render_log` — с этого момента каждый показ имеет цену (render_miss).

## Что происходит при SessionStop

Одна цепочка, три транзакции: (1) закрытие всех лабильных окон → дифф-судья → ревизии реконсолидатора, обновление pathways, чеканка коррекций; (2) клиринг гроссбуха: когортный earn, render_miss, discovery, yield_bonus, перекалибровка α/β, доля сессии-фонда; (3) проспектива: матч погашений, suspension-фреймы, эрозия несработавших намерений. Затем счётчики: пора ли переобучать словарь, пора ли GC. `memory_session` — тот же вход, что у всех: через шлюз ступени 2.

Изменения вне core: `memory_add/session` — через шлюз (ступень 2); `memory_recall/context/search` — открывают окно и путь (ступень 3); `memory_gc` — вызывает `gc.rs`; хуки — добавить PostToolUse-хук (пишет в act_trace через CLI `aurelius trace`), расширить Stop-хук цепочкой ступеней 4→5→6, расширить SessionStart рендером v2. Волны внедрения: (1) модули 1–2 — WAL сразу начинает копиться, ничего не ломая; (2) 3–4 — шлюз включается в advisory-режиме (логирует, не отбрасывает) одну неделю для подбора порога NCS; (3) 5–7 — окна и судья; (4) 8–10 — проспектива, рендер, GC. Обратная совместимость: существующие узлы получают `state='circulating'`, ревизию rev=1 без окна-причины (grandfathered) и нулевые счета — они заработают ценность или обанкротятся честно, как все.

**Позиционирование (важно для README):** не «первая реконсолидация» и не «первый surprise-гейт» — это ложь, prior art задокументирован. Честная формула: *outcome-grounded, compression-priced memory* — ценность записи измеряется, а не оценивается: в битах на будущем входе и в исходах действий по сырым следам; забывается путь, а не знание; всё аудируемо и обратимо через append-only леджер и ревизии.
