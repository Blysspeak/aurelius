# Quickstart: фикстура, eval, три поведения

Всё помеченное **НОВОЕ** ещё не существует в дереве — это контракт фазы из `plan.md`, не команда,
которую сегодня можно набрать. Остальное проверено против рабочего дерева 2026-09-08 и снабжено
`файл:строка`. Linux сверху, Windows 11 (PowerShell) снизу — вторая форма даётся только там, где
команды действительно расходятся. `env VAR=… cmd` работает и в bash, и в fish; PowerShell требует
`$env:`.

**Есть**: `au db backup --out` (VACUUM INTO, `commands.rs:3252`), `au db check [<path>] [--full]`
(`crates/au/src/main.rs:365-371`, путь — необязательный), `au home use|current|reset`
(`crates/au/src/main.rs:333`), `au snapshot [--project <p>] [--json|--hook]`,
`au recall <QUERY>|--prefix` (`commands.rs:806-817`), `AURELIUS_HOME` (`home.rs:24`; база ищется
как `<home>/aurelius.db`, `db.rs:41,48`).
**Нет**: `au eval` (фазы A, F), `au recall --topic` (B), `au recognize --hook` (D),
`au db reindex-stems` (E), каталог `fixtures/eval/`; новые модули `graph/rank.rs`,
`graph/render.rs`, `graph/recognize.rs`, `eval.rs`.

**Допущение о рабочем дереве.** Флаг `au recall --prefix` — и вместе с ним `graph/pickup.rs`,
`graph::by_degree_then_recency`, `graph::subgraph_degree` — живёт **только в незакоммиченном
рабочем дереве** ветки `feat/contour-wave-1`: в `git HEAD` его нет (проверено `git grep` по HEAD,
2026-09-08). Взявший ветку по коммиту этих команд и символов не найдёт.

Нормативные документы, которым этот подчиняется: формат кейсов — `contracts/eval-cases.md`,
флаги и коды возврата — `contracts/cli.md`. Расхождение здесь читается как ошибка здесь.

## 1. Фикстура

```bash
au db backup --out ~/tmp/aurelius-2026-09-08.db && au db check ~/tmp/aurelius-2026-09-08.db --full
```
```powershell
au db backup --out $env:USERPROFILE\tmp\aurelius-2026-09-08.db; au db check $env:USERPROFILE\tmp\aurelius-2026-09-08.db --full
```

`--out` отказывается писать поверх существующего файла (`commands.rs:3264`). VACUUM INTO —
единственный корректный способ копии: живая база под WAL открыта на запись у хуков, `cp` даёт
рваный файл. Список подстановок для обезличивания — владельца, ниже только механика; правки идут
по копии.

```bash
sqlite3 ~/tmp/aurelius-2026-09-08.db <<'SQL'
DROP TRIGGER IF EXISTS act_trace_ro;      -- append-only, db.rs:841
DROP TRIGGER IF EXISTS act_trace_nodel;   -- db.rs:844
UPDATE nodes SET label = replace(label,'СТАРОЕ','НОВОЕ'),
                 note  = replace(note, 'СТАРОЕ','НОВОЕ'),
                 data  = replace(data, 'СТАРОЕ','НОВОЕ');
UPDATE act_trace SET payload = replace(payload,'СТАРОЕ','НОВОЕ');
DELETE FROM nodes WHERE node_type='"config"'
                    AND json_extract(data,'$.kind')='secret_ref';   -- crates/aurelius-core/src/secret.rs:55
DELETE FROM search_cache;                 -- кэш веб-поиска: запросы владельца
INSERT INTO act_trace_fts(act_trace_fts) VALUES('rebuild');
VACUUM;
SQL
```

Windows: тот же SQL файлом, `sqlite3.exe … ".read scrub.sql"` — heredoc в PowerShell нет.
`sqlite3` в Linux — одноимённый пакет, в Windows — sqlite-tools с sqlite.org в PATH.

Три места, где легко ошибиться:

- `act_trace` защищена триггерами `RAISE(ABORT, 'act_trace is append-only')` (`db.rs:841`,
  `db.rs:844`); без их снятия `UPDATE`/`DELETE` падает. Снимать можно только на копии.
- `nodes_fts` пересобирать не надо — есть `AFTER UPDATE`-триггер `nodes_au` (`db.rs:1037`). У
  `act_trace_fts` триггер только `AFTER INSERT` (`db.rs:850`), отсюда явный `rebuild`.
- `claim` лежит в `nodes.data`, а не в `note` (`graph/search.rs:168-169`,
  `Provenance::from_data`): без подстановки по `data` обезличено только то, что видно глазом.

Проверка хвостов: `SELECT count(*) FROM nodes WHERE label LIKE '%СТАРОЕ%' OR note LIKE '%СТАРОЕ%'
OR data LIKE '%СТАРОЕ%';` → 0, то же по `act_trace.payload`.

### 1.2 sha256 в строку `meta`

```bash
sha256sum fixtures/eval/aurelius-2026-09-08.db
```
```powershell
Get-FileHash fixtures\eval\aurelius-2026-09-08.db -Algorithm SHA256
```

Хеш считается по **распакованному** `.db` и вписывается в `meta.fixture_sha256` первой строки
`fixtures/eval/cases.jsonl` (`contracts/eval-cases.md` §1.1). Не сошёлся при прогоне — код `14`,
чисел нет вовсе: несравнимый результат хуже отсутствующего.

Первая строка файла кейсов — ровно она:

```json
{"meta": {"version": 1, "as_of": "2026-09-08T00:00:00Z", "fixture": "fixtures/eval/aurelius-2026-09-08.db", "fixture_sha256": "<hex>"}}
```

Дальше по строке на кейс, дискриминатор — `kind` (не `check`), пять значений: `recall_top5`,
`morphology`, `refusal`, `snapshot_contains`, `recognize_feed`. Полы: `recall_top5` ≥ 30,
`morphology` ≥ 20, `refusal` ≥ 5 — **не менее 55 кейсов** (FR-027). У `snapshot_contains` и
`recognize_feed` пола нет, их закрывают ворота фаз: на `snapshot_contains` **частью** закрывается
фаза C; на половине `recognize_feed` с `expect.empty = true` — фаза D (механическая проверка
FR-017 и SC-005); на половине с фактами — фаза G.

**Когда какой пол заполняется — это условие сравнимости, а не деталь плана.** Оба пола видов, у
которых есть базовая линия, — 30 `recall_top5` и 20 `morphology` — **пишутся в фазе A**, и набор
после этого **заморожен**: фаза F не добавляет ни одного кейса этих двух видов, она добавляет
кейсы отказа и пересчитывает «после» на том же наборе. Базовая линия, снятая на десяти кейсах, и
результат, снятый на тридцати, несравнимы, и разница между ними не значит ничего.

Размер после zstd не измерен. Живая база на 2026-09-08 13:50 — 114 376 704 байта (`ls -l`), и она
растёт по ходу работы: сверять размер копии с этим числом бессмысленно, сверяется sha256.

## 2. Eval: число «до» и число «после»

```bash
au eval fixtures/eval/cases.jsonl                                 # НОВОЕ
au eval fixtures/eval/cases.jsonl --db fixtures/eval/aurelius-2026-09-08.db --json
```

`AURELIUS_HOME` здесь **не участвует**. Фикстуру называет `--db`; без флага берётся `meta.fixture`
из первой строки файла кейсов; нет ни того, ни другого — код `1`, угадывать нечего
(`contracts/cli.md` §2). Windows отличается только видом пути (`fixtures\eval\…`).

`--live` гонит те же кейсы по живой базе (FR-025): в шапке и в конце — `НЕСРАВНИМО: живая база`,
в `--json` — `comparable: false`. Такие числа в `research.md` не пишутся.

`--now <RFC3339>` перекрывает `meta.as_of`. Системные часы на пути eval запрещены: свежесть
`R = 1 / (1 + age_days / 180)` от «сейчас» переворачивала бы порядок близких кандидатов между
прогонами, а кейс `snapshot_contains`, ожидающий «2 дн. назад», зеленел бы ровно один день.

Печатается доля пройденных **по каждому из пяти видов** (FR-024), знаменатель — пригодные кейсы
вида, то есть все минус `SKIP`; провал показывает ожидаемое и полученное, а не «FAIL» (FR-026).
Форма отчёта целиком — `contracts/eval-cases.md` §5.

Коды возврата (`contracts/cli.md` §2): `0` — прогон состоялся, провалы названы в отчёте; `1` —
файл кейсов не понят или фикстура не названа; `2` — фикстура не открывается; `14` — прогон
несравним (sha256 разошёлся, незнакомая `meta.version`, проверке потребовалась запись). Провал
кейса кода не меняет. Файл ниже пола FR-027 — тоже `0` плюс строка в stderr
`au eval: ниже пола FR-027 — recall_top5 12/30`.

Числа пишутся в `specs/010-waking-memory/research.md`: «до» — фазой A **до первой правки поиска**
(SC-002), число каждой фазы рядом (Constitution V), «после» — фазой F.

**Два утверждения о знаке, которые нельзя путать.** Фаза F закрывается на **строго большем**
базовой линии по `recall_top5` и `morphology` (SC-002, SC-003) — это порог входа, приёмка фазы.
Принцип конституции «фаза не считается закрытой, если её число ниже предыдущего» — про другой
момент: про прогоны **после** того, как фаза уже закрыта, то есть про храповик от регрессии.
Слитые в одно, они дают ложный вывод «число, равное базовой линии, фазу закрывает»: не закрывает.

Детерминизм — два прогона подряд обязаны дать побайтово одинаковый stdout, включая `digest`;
фикстуру перед вторым перераспаковывать не нужно — `au eval` открывает её `db::open_readonly`
(публичной её делает **фаза A**, см. 3.3) и следа не оставляет.

## 3. Три поведения руками

### 3.1 Снимок начинается с «где остановились»

```bash
env AURELIUS_HOME=~/tmp/eval-home au snapshot --project aurelius | head -30
env AURELIUS_HOME=~/tmp/eval-home au snapshot --project aurelius --json
cargo test -p aurelius-core json_facts_shape_is_fixed_and_empty_means_nothing_to_say
```
```powershell
$env:AURELIUS_HOME="$env:USERPROFILE\tmp\eval-home"; au snapshot --project aurelius | Select -First 30; Remove-Item Env:AURELIUS_HOME
```

Обе формы обязаны показать блок, но приходит он в них **разными путями**, поэтому проверяются обе.
Три markdown-формы собирает `graph::build_snapshot` (`graph/snapshot.rs:299`): блок рождается
там, а не в обработчике флага, и приходит во все три сам. **JSON-форму собирает другая функция —
`graph::snapshot_facts` (`graph/snapshot.rs:268`)**; развилка видна на месте
(`commands.rs:2731-2734`:
`if json_out { snapshot_facts } else { build_snapshot }`), поэтому поле `state` вставляется в неё
**отдельной правкой и из того же вычисления**, а не приезжает из `build_snapshot`. Обвязка зовёт
обе двери: `au snapshot --project <p>` без `--json` (`ulika/hooks/lib/restore.mjs:185`) и с
`--json` (`ulika/hooks/lib/brief.mjs:191`). **Флаг `--hook` путём доставки не является и в
проверке не участвует** — он и не совместим с `--json` (`conflicts_with = "hook"`,
`crates/au/src/main.rs:649-650`).

Ожидаемо: первой секцией `## 1 · Где остановились` — проект, ветка, активная задача, до трёх
решений, блокеры, давность; остальные секции сдвинуты на единицу (`## 2 · Владелец` и далее);
заголовок `# Память Aurelius · <scope> · <ts> UTC` не изменился (`graph/snapshot.rs:349-365`).
В JSON — прежний `facts[]` с `kind`/`text`/`at` и прежним форматом `at`, working state отдельным
полем верхнего уровня `state` (FR-002b); тест формы — `graph/snapshot.rs:581`.

Осторожно: `au snapshot` **пишет** — раз в сутки зовёт `graph::consolidate`
(`commands.rs:2717-2727`). Поэтому у него отдельный home (1.1), а не фикстура eval; после проверки
распаковать `~/tmp/eval-home/aurelius.db` заново, если важна повторяемость.

Бюджет 300 токенов (FR-001, SC-006) авторитетно печатает вид `snapshot_contains` в `au eval`
(поле `max_chars`). Ручной прокси — только «влезает в экран»: соотношение символов к токенам для
русского здесь не измерялось.

### 3.2 Recall отказывает на широкой теме и говорит прозой

```bash
au recall --topic au                                  # НОВОЕ, фаза B
au recall --topic "стемминг русской морфологии" --json
```

Флаг аддитивный: `au recall <QUERY>` и `au recall --prefix` не тронуты (`commands.rs:806-817`,
`commands.rs:825`). Именно он делает SC-001 проверяемым командой, а не глазами через MCP-клиента.

**Это ручной шаг, и зелёный кейс eval его не заменяет.** Кейс отказа внутри `au eval` идёт **по
фикстуре**: она заморожена, df терма в ней постоянен, вердикт повторяем побайтово — это и есть
ворота фазы B. Сам SC-001 — **отдельный ручной прогон `au recall --topic au` по ЖИВОЙ базе, без
подмены home**, потому что df терма в фикстуре и в живой базе — разные числа, а живое растёт
каждый день. Зелёный кейс на фикстуре SC-001 не доказывает, и наоборот. Запись прогон не делает:
`access_count` не инкрементируется (FR-014a), потому что `touch_node` зовёт **только**
MCP-обработчик `memory_recall` (`handlers/session.rs:266`) — ядро, `au recall --topic` и
`au eval` не зовут его никогда.

Ожидаемо на `--topic au`: код `0`, узлы не отданы (FR-006), на stdout — ровно этот текст
(`contracts/cli.md` §4):

```console
$ au recall --topic au
тема слишком широкая: терм «au» встречается в 3,5 % узлов и тему не сужает. Второе слово
рядом не поможет — термы склеиваются через OR, поэтому «au judge» шире, чем «judge».
Замените широкий терм парой узких: «стемминг recognize», «judge фикстура». Либо сузьте
область: --project aurelius.
$ echo $?
0
```

Переносы — вёрстка терминала; подстрока `не сужает` не разрывается никогда: на неё смотрит
нормативный кейс `refuse-topic-au` (`contracts/eval-cases.md` §6). Числа совпадений в прозе **нет**
— его несёт своё поле объекта отказа (`contracts/mcp.md` §2.1), им FR-006 и закрывается. Пары
`«стемминг recognize»`, `«judge фикстура»` — иллюстрация формы. Правило порождения: каждая
предложенная тема собирается **только из термов ниже вето** и несёт **не менее двух** из них,
чтобы пройти тот самый детектор, который её и выдал; одиночный терм предлагать нельзя — по
собственному правилу пакета (значимых термов меньше двух) он получил бы `topic_too_narrow`
(`contracts/cli.md` §4, `contracts/mcp.md` §2.1). Хвост `--project` — сужение области, а не тема,
и под эту проверку не попадает. Сегодня тот же вопрос через `memory_recall` даёт 162 совпадения,
760 узлов за кадром, 12 показанных — это исходная точка.

На нормальной теме: ≤ 12 записей одного проекта, число узлов других проектов названо (FR-009),
каждая запись — строка `тип [проект] дата — текст` без UUID и наносекунд (FR-010), прежние поля
JSON на месте, `prose` — добавка (FR-012).

Воспроизвести упавший кейс `recall_top5` по фикстуре можно только подменой home — `--db` у
`au recall` нет (`contracts/cli.md` §4), есть только `--now`:

```bash
env AURELIUS_HOME=~/tmp/eval-home au recall --topic "…" --now 2026-09-08T00:00:00Z
```

Не проверять через `au search` и `au context`: обе идут через `open_and_ensure`
(`commands.rs:19`), который индексирует текущий каталог побочным эффектом, то есть пишет в
подставленный home. `au recall` открывает базу напрямую `db::open` (`commands.rs:829`) и этим не
занимается.

### 3.3 Знакомая сущность узнаётся на самом ходу

```bash
echo '{"hook_event_name":"UserPromptSubmit","prompt":"что там в бустиксе?","cwd":"'$PWD'","session_id":"manual"}' | au recognize --hook
sqlite3 ~/.local/share/aurelius/aurelius.db "SELECT count(*), sum(access_count), max(last_accessed_at) FROM nodes;"
```
```powershell
'{"hook_event_name":"UserPromptSubmit","prompt":"что там в бустиксе?","cwd":"C:/workSpace/aurelius","session_id":"manual"}' | au recognize --hook
```

Имена полей проверены по обработчику ulika на том же событии — `input.prompt` и
`hookSpecificOutput.additionalContext` (`ulika/hooks/route.mjs:21,91-93`; `additionalContext`
объявлен именно на 93-й, поэтому диапазон не сужается до `:91-92`); оба висят на
`UserPromptSubmit` одновременно, их `additionalContext` склеиваются, 50 токенов узнавания
считаются с учётом этого (FR-014b).

Ожидаемо: одна строка, начинающаяся с маркера, — `В памяти: <имя> — <давность>, <N> открытых`
(FR-016), ≤ 50 токенов. Маркер `В памяти:` обязателен: в склейке с ulika без него строка
неотличима от чужого текста. Правило хвоста одно: **печатается не более трёх имён; хвост
«; и ещё N знакомых» печатается, когда узнано больше трёх, N = узнано − 3, форма одна при любом
N ≥ 1**. Порога «пять и более» нет, склонения по N — тоже. На сообщении без знакомых сущностей и
на сообщении со словом `au` (df = 3,5 %) — **ноль байт** и код 0 (FR-017): не `{}`, не пустой
конверт, не перевод строки.

Время подачи меряется ручной формой, а не секундомером снаружи — снаружи на Windows в счёт попадёт
ещё и старт процесса:

```bash
au recognize --json "что там в бустиксе?"
```

Поле `elapsed_ms` — то самое число, по которому ворота фазы D считают p95 ≤ 200 мс (SC-004):
двадцать ходов, двадцать значений, девятнадцатое по возрастанию. Полный перечень полей машинной
формы — `contracts/cli.md` §1, второго перечня в пакете нет. Текущее время наивной реализации
**не измерено**.

Три числа из `sqlite3` до и после обязаны совпасть (FR-014a, SC-004). Именно они, а не mtime
маркера `last-write`: `db::mark_write` зовётся только из `graph/crud.rs:115` и
`crates/aurelius-core/src/tasks.rs:668`, а `touch_node` (`graph/crud.rs:392`) инкрементит
`access_count` молча, маркера не трогая. Сегодня `memory_recall` инкрементит его на каждом показе
(`handlers/session.rs:266`) — ровно то, чего подача делать не должна.

Держится это одним решением: соединение открывается **`db::open_readonly`** (сегодня приватна,
`db.rs:154`; сделать её `pub` — работа **фазы A**, а не D: первый её потребитель — `au eval`,
который обязан открыть фикстуру только на чтение на самом первом прогоне, а фаза D пользуется уже
публичной функцией). `db::open` (`db.rs:96`) на этом пути запрещён — он
зовёт `ensure_wal` (`PRAGMA journal_mode=WAL`, кратковременный эксклюзивный захват), ставит
`synchronous=FULL` и прогоняет `migrate()`. Хук хода не имеет права быть первым запуском после
смены схемы.

Полная проверка (SC-007) — в Claude Code: поработать, `/clear`, спросить «где мы остановились?» и
убедиться по транскрипту, что до ответа нет ни одного вызова инструмента; затем упомянуть знакомую
сущность и убедиться, что модель не сказала «сейчас поищу».

**Область покрытия — старт сессии и `/clear`, и только они.** Восстановление ulika срабатывает на
`RESTORE_ON = new Set(['clear', 'startup'])` (`ulika/hooks/lib/restore.mjs:58`); `compact` и
`resume` исключены сознательно. Проверять фичу на них нельзя — они вне её области.

## 4. Переиндексация и откат

```bash
au db backup --out ~/.local/share/aurelius/backups/aurelius-pre-stems.db
au db reindex-stems                                                       # НОВОЕ, фаза E
```
```powershell
au db backup --out $env:APPDATA\aurelius\backups\aurelius-pre-stems.db
au db reindex-stems
```

Команда называется `au db reindex-stems`, а не `au reindex --stems`: сегодняшний `au reindex` —
про индексацию файлов проекта в граф, стем-сборка идёт по всей таблице узлов и на файлы не
смотрит. `au db` — существующая группа обслуживания базы (`DbAction`,
`crates/au/src/main.rs:363`: `check`, `backup`), и `au reindex` эта спека не трогает вовсе
(`contracts/cli.md` §3). Флагов у команды нет: она пересобирает `nodes_stem_fts` всегда.

Автокопии уже есть: `au db backup --hook` на `SessionStart` держит 7 штук в
`~/.local/share/aurelius/backups/` (`%APPDATA%\aurelius\backups\`) с троттлингом 24 часа
(`hooks.rs:169-215`) — именованная нужна потому, что троттлинг мог съесть сегодняшнюю.

Стем ложится в **отдельную самостоятельную таблицу**, а не в колонку `nodes_fts`:

```sql
CREATE VIRTUAL TABLE nodes_stem_fts USING fts5(label, note);
```

Свой контент (без `content=`), `rowid` совпадает с `nodes.rowid`, **`nodes_fts` не меняется ни на
строку DDL** (`db.rs:1021` остаётся как есть). Это измерение, а не вкус: `research.md` B.1
показал, что фантомная колонка в таблице с `content='nodes'` навсегда ломает
`INSERT INTO nodes_fts(nodes_fts) VALUES('rebuild')` и чтение колонок; решение — `research.md` B.4.

- Миграцию схемы (14 → 15, `SCHEMA_VERSION`, `db.rs:8`) применяет `db::open` при **первом же**
  запуске нового бинарника, то есть первый сработавший хук, а не `au db reindex-stems`. Миграция
  создаёт `nodes_stem_fts` пустой; явными остаются заливка и сообщение о ней (FR-022).
- Вперёд деградации нет: пока `nodes_stem_fts` пуста, поиск идёт по `nodes_fts` ровно как сегодня,
  плюс одна строка **в stderr**: `au: стеммированный индекс пуст — поиск идёт по точному токену;
  собрать: au db reindex-stems`.
- Назад «просто вернуть бинарник» **нельзя**: `migrate()` отдаёт `SchemaTooNew`, когда версия
  файла больше поддерживаемой (`db.rs:472`).

Откат стемминга — одна строка, база остаётся боевой:

```bash
sqlite3 ~/.local/share/aurelius/aurelius.db "DROP TABLE IF EXISTS nodes_stem_fts;"
```

Версия схемы при этом остаётся 15, то есть старый бинарник всё равно не запустится; чтобы вернуть
и её, нужен полный откат — закрыть Claude Code (его хуки пишут), затем:

```bash
cp ~/.local/share/aurelius/backups/aurelius-pre-stems.db ~/.local/share/aurelius/aurelius.db
rm -f ~/.local/share/aurelius/aurelius.db-wal ~/.local/share/aurelius/aurelius.db-shm
au db check --full
```
```powershell
Copy-Item $env:APPDATA\aurelius\backups\aurelius-pre-stems.db $env:APPDATA\aurelius\aurelius.db -Force
Remove-Item $env:APPDATA\aurelius\aurelius.db-wal,$env:APPDATA\aurelius\aurelius.db-shm -EA 0
au db check --full
```

Хук откатывается отдельно и только он один: за всю спеку `plugin/hooks.json` правится **один раз,
в фазе D** — добавляется группа `UserPromptSubmit` с `au recognize --hook`. Фаза C манифест не
трогает вовсе (блок приходит из `build_snapshot`). Откат — убрать эту группу (сегодня в файле
только `SessionStart`, `PostToolUse`, `Stop`), вернуть `crates/au/tests/plugin_manifest.rs:157` к
шести именам (`["db","judge","reindex","skills","touch","trace"]`) вместе со словом «six total» в
сообщении, затем `claude plugin marketplace update blysspeak && claude plugin update aurelius`.
Без правки теста `cargo test --workspace` краснеет начиная с фазы D и на всех последующих.

Отдельно про машину: установленный плагин 3.4.4 всё ещё несёт запись `["snapshot","--hook"]`
(`~/.claude/plugins/cache/blysspeak/aurelius/3.4.4/hooks.json:7`), которой в рабочем дереве уже
нет. После `claude plugin update` расхождение исчезнет; до него установленная и репозиторная
версии манифеста отличаются, и путать их при откате нельзя.
