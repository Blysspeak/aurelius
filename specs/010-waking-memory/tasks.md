противоположные по смыслу (выбор хранения стемов, «вынос компаратора»). Сохранять старые номера
при таком объёме значило бы получить дыры и хвосты вида T055a. Соответствие фаз прежнее: A…G.

**Чего здесь нет намеренно.** Формат `fixtures/eval/cases.jsonl` — только
`contracts/eval-cases.md`; типы и имена полей — только `data-model.md`; форма JSON на проводе —
только `contracts/mcp.md`; флаги, коды возврата и формы вывода команд — только
`contracts/cli.md`. Задача ниже **ссылается** на нужный раздел и не повторяет его: прежняя
редакция этого файла писалась за семь минут до появления шести из девяти документов и потому
фиксировала типы и формы прямо в тексте задач — теперь у каждой из этих вещей есть владелец, и
второй экземпляр описания расходится с ним молча.

**Tests**: конституция (принцип V) требует тест на каждое поведение — тесты идут задачами
реализации, не отдельной фазой.

**Organization**: по фазам A–G из плана (раздел «Фазы реализации»). Метка `[USn]` показывает,
какую историю спеки фаза закрывает; `[P]` — задача трогает файлы, которых не трогает соседняя, и
не ждёт незакрытой.

## Implementation Strategy

MVP = A + B + C: измеримый recall, честная выдача и снимок, который знает, где остановились.
Это уже меняет ощущение каждой сессии и **не требует ни одной правки `plugin/hooks.json`**.
D добавляет подачу на каждом ходу и единственный новый хук — вместе с правкой пина подкоманд.
E снимает зависимость от падежа. F закрывает измерение. G — последним, потому что несёт
единственный риск во всей спеке: подать устаревший или чужой факт; включается только после того,
как F покажет попадание в топ-5 по именам сущностей.
